# Re-pilot of the redesigned S2, 2026-11-12: the investigation is still under the floor

Outside the pre-registered runs. The design and the criterion, both written before this ran,
are in `S2-REDESIGN.md`. Both sessions ran in the **rule** arm (shipped pack plus the
staged rule) on the redesigned S2 (overlay `fixture-s2/`, eight CI logs). There was one
session per reader and no reruns; neither session was void. Scrubbed records and transcripts
are in `pilot/pilot2-S2-*`. Every figure below comes from those records and the raw
transcripts, not from what the sessions said about themselves.

## Result

**The redesign fails the criterion `S2-REDESIGN.md` fixed before the run.** The
investigation (t6 and t7) added fewer than 10,000 tokens to the main context in both
sessions. Neither session used a subagent, so the main-context figure is the
investigation's whole load. The 10,000 figure is the pre-registration's floor for B1. That
floor applies to a control-arm median of ten sessions, not to single pilot sessions, so this
pilot can't test the floor itself. It used the same number as the bar for the redesign, and
the number is not lowered. The finding goes on the board, and the full run is not proposed on
this design.

## How they got there (from the tool calls)

- **Sonnet** found the flaky tests with one `grep ... | sort | uniq -c` over the eight logs
  and a per-file summary of `FAIL:` lines. In t7 it ran one `cat` over all five modules
  plus `util.py`, then read the registry. It tried a seed sweep (a shell `for` loop),
  which the harness's command list denied. It read every code path, as the design
  intended, and the whole t7 turn still added only 4,342 tokens, its answer included.
  Five modules of 30 to 60 lines are not heavy.
- **Opus** listed the failures with one grep, then used a pattern grep
  (`sort|set\(|hash|random|order`) across the modules. It read `sed -n` line ranges of the
  modules, and the two generated files whole. It never opened the tests. Its seed sweep
  (a `for` loop) was denied too, and it then ran the five test modules twice without a seed.
  This is the path `S2-REDESIGN.md` warned about: spotting the common idiom with narrow
  reads instead of reading each path.
- Both fixed all five modules in `ledger/`, not the generated registry, and showed the fix
  by running the suite several times. Sonnet also wrote a seed-sweep script under `/tmp`,
  outside the working copy. It never ran: one call failed to import it and the other was
  denied. Denied calls changed what both sessions read. Sessions with broader permissions
  might have spent more, or less, on the sweep.

## What this says about the design, not the rule

- Breadth (more symptoms, more runs) raised the figure only modestly. Capable readers
  grep for the shared idiom, or read small files cheaply. A cause spread across small files
  does not make the reading heavy.
- Of the four rule-arm S2 sessions that reached the investigation (the first pilot's two
  reruns and these two; its two void sessions stopped after t5), **none used a subagent**. At these
  sizes the rule's "run it in a fresh context" clause has never fired. That fits the
  rule's own condition (delegate when you need only the result), since an 8k to 9k
  investigation is cheap to keep in context. It also means the benefit endpoint cannot
  move until the investigation is much heavier than this.

## Cost

Both sessions together: **$1.25** at the CLI's list-price estimate. They ran through the CLI
with authentication supplied by the environment's proxy (`apiKeySource: none` in each
session's `init` event); the transcript shows no billing path beyond that.
